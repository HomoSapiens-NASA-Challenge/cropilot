# Contextual evidence assistant

The assistant helps an agronomist compare published scenarios, with resilience, water and
soil cover first. It uses the existing case bundles and, after authentication, the selected
planner run. Live OpenAI and browser checks returned sourced comparisons; this does not
validate the agronomic models or establish an RL advantage. No new satellite measurements,
forecasts or farm records were acquired. Keep this read-only scope for the demo; next evaluate
more questions with an agronomist before adding simulation actions or voice.

## Try it

1. Install the repository dependencies with `pnpm install --frozen-lockfile`.
2. Copy `.env.example` to `.env` if needed. Keep `OPENAI_API_KEY` in the ignored root
   `.env.local`, never in a `VITE_` variable. Set `ASSISTANT_PUBLIC_ENABLED=true` there
   only when the public demonstration should make paid calls.
3. Run `pnpm --filter @cropilot/backend dev` and `pnpm --filter @cropilot/webapp dev` in
   separate terminals. The standard full `pnpm dev` also works with configured database/auth.
4. Open `http://localhost:5173/case/pergamino` and choose **Ask Cropilot**.
5. Ask: “Compare the rotations at 1 m depth and 50% initial water. Does this predict floods?”
   Expand the evidence tables and sources. Follow up with a supported calendar shift.

The public case and assistant do not require a database connection or login. Without the
auth service, the existing optional session request returns 502 through the Vite proxy;
the public page handles that as signed out. Private planner chat needs real authentication
and simulator inputs, just like the existing planner. After a completed run, its **Ask Cropilot**
button sends the run ID; the backend resolves the owner from the JWT.

UI labels are English; answers follow the question's language. Conversations live only in
the mounted panel, survive closing/reopening it and reset on region/run change. The last
three exchanges are sent for follow-ups. **New conversation** clears the local thread.

## Implementation and boundaries

- `app/modules/assistant`: typed requests, Responses API orchestration, evidence tools and
  process-wide usage gate. Generated OpenAPI types and TanStack mutations drive the UI.
- `components/assistant-panel.tsx`: shared public-case and private-planner panel. Tables
  are built from server evidence, not numbers generated by the language model.
- `app/modules/mcp/{service,schemas,__init__}.py`: reused byte-for-byte from PR #10,
  `15c1c00`. This branch does not merge its MCP transport, interactive card or mobile work.
- Functions: `list_cases`, `find_analog_years`, `compare_rotations`, `get_field_evidence`,
  and owner-scoped `get_planner_result`. The selected region is fixed by the request;
  model tool arguments cannot substitute a different region or private owner.
- Exact water combinations only. Missing water stays missing. Analog episode tables and
  full-history paired counts are separate; water totals cover three campaigns.
- The planner card shows **optimum minus baseline**, its existing held-out intervals and
  conclusion. It does not label these as RL-minus-greedy intervals or food CVaR.
- No new runs, edits, external messages, voice, web browsing or native-mobile UI in this
  increment. Use the existing planner wizard to change weights and launch a run.

## Configuration and data sent to OpenAI

`OPENAI_MODEL` defaults to `gpt-5.4-mini` (verified available for the local key). The backend
reads `.env`, then `.env.local`, with process environment taking precedence. The production
Compose file passes the four assistant settings to the backend only. Compose users can
load `.env.local` with an explicit additional `--env-file`; it is not copied into the image.

The provider receives the question, bounded recent history, source/method metadata,
selected public evidence and, only for authenticated planner chat, the caller's selected
simulation result. Credentials and authentication tokens are never included in those inputs.
Responses use `store=false`; this is not a claim of zero provider retention.

Public paid access defaults to disabled. Both routes share a limit of 60 messages/hour
(`ASSISTANT_REQUESTS_PER_HOUR`) and two concurrent requests. Each message permits up to
four provider requests, three tool calls, 2,400 output tokens per request and a 35-second
SDK timeout per request, without automatic provider retries. Tool payloads are capped at
128 KiB. Limits are in-memory and reset on restart; deploy one backend process as already
required by the planner. Use an external persistent limiter before scaling publicly.

Every answer paragraph requires at least one known source ID. Unknown sources fail closed;
unavailable provider errors expose no provider body. Schema/source checks do **not** prove
that every natural-language claim is supported: inspect the underlying table and evaluate
the answers. User history is untrusted, and numerical questions re-read tools each turn.

The prompt explicitly preserves spatial scale, provenance and time. JAS ONI is available
after a late-August decision, so these analog selections are retrospective. Water excess
is not a validated flood forecast. Soil carbon and food CVaR are not current planner goals.

## Verification

`uv run pytest tests/test_assistant.py -q` covers exact water values, invalid combinations,
missing regional water, invented/missing citations, owner checks, rejected private IDs on
the public endpoint, concurrency/budget release, real SDK tool round trips with a mocked
HTTP transport, bounded tool loops and sanitized provider errors. No live calls in tests.

Local live check on 2026-11-15: the browser comparison returned HTTP 200 in 5.8 seconds
(one observation, not a latency benchmark; a later check took 13.3 seconds),
called `compare_rotations` and supplied ten
source records. Checked desktop 1440×1000 and mobile 390×844, evidence expansion and
conversation reset. No page exceptions or horizontal mobile overflow. The one observed
console error was the optional auth request's 502 with auth not running.

Private ownership is tested offline. A real Google-login-to-planner conversation has not
been exercised in this local environment. Existing optional model tests skip when their
separate datasets/environments are absent; no scientific validation is inferred from UI tests.
