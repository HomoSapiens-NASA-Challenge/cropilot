# Contextual evidence assistant

The assistant helps an agronomist compare published scenarios, with resilience, water and
soil cover first. It uses the existing case bundles and, after authentication, the selected
planner run. Live OpenAI and browser checks returned sourced comparisons; this does not
validate the agronomic models or establish an RL advantage. No new satellite measurements,
forecasts or farm records were acquired. Keep this read-only scope for the demo; next evaluate
more questions with an agronomist before adding simulation actions. Recorded voice turns
are part of this increment, with editable transcription and an optional spoken excerpt.

## Try it

1. Install the repository dependencies with `pnpm install --frozen-lockfile`. Install
   FFmpeg and ensure `ffmpeg` is on PATH for local voice input; the production backend
   image includes it. Text chat does not require FFmpeg.
2. Copy `.env.example` to `.env` if needed. Keep `OPENAI_API_KEY` in the ignored root
   `.env.local`, never in a `VITE_` variable. Set `ASSISTANT_PUBLIC_ENABLED=true` there
   only when the public demonstration should make paid calls.
3. Run `pnpm --filter @cropilot/backend dev` and `pnpm --filter @cropilot/webapp dev` in
   separate terminals. The standard full `pnpm dev` also works with configured database/auth.
4. Open `http://localhost:5173/case/pergamino` and choose **Ask Cropilot**.
5. Ask: “Compare the rotations at 1 m depth and 50% initial water. Does this predict floods?”
   Expand the evidence tables and sources. Follow up with a supported calendar shift.
6. Choose **Record question**, allow microphone access, then **Stop recording**. Review
   and edit the transcript before **Send**. **Spoken reply** reads an excerpt; the full
   answer, limitations and sources remain visible. Use the audio controls to pause/replay.
   Microphone capture requires HTTPS or localhost; a LAN HTTP address will not work.

The public case and assistant do not require a database connection or login. Without the
auth service, the existing optional session request returns 502 through the Vite proxy;
the public page handles that as signed out. Private planner chat needs real authentication
and simulator inputs, just like the existing planner. After a completed run, its **Ask Cropilot**
button sends the run ID; the backend resolves the owner from the JWT.

UI labels are English; answers follow the question's language. Conversations live only in
the mounted panel, survive closing/reopening it and reset on region/run change. The last
three exchanges are sent for follow-ups. **New conversation** clears the local thread.

## Implementation and boundaries

- `app/modules/assistant`: typed requests, Responses API orchestration, evidence tools and
  process-wide usage gate. Generated OpenAPI types and TanStack mutations drive the UI.
- `components/assistant-panel.tsx`: shared public-case and private-planner panel. Tables
  are built from server evidence, not numbers generated by the language model.
- `apps/mobile/src/features/case/assistant`: the Expo app's **Ask Cropilot** screen
  (`/case/[zoneId]/ask`, reached from Home and the case screen). Same public request,
  history and evidence tables as the web panel; no planner chat, since the app cannot run
  the planner. Voice uses `expo-audio` (m4a/AAC sent as `audio/mp4`, webm on Expo Web)
  and plays spoken replies from a cache file deleted with the conversation. Native
  microphone and speaker have not been tested on a device.
- Evidence selectors come from the shared MCP module, retaining PR #12's server,
  `/api/mcp` mount, card and mobile work. The team merged #12 and #11 while this increment
  was in progress; voice now builds on updated main.
- Functions: `list_cases`, `find_analog_years`, `compare_rotations`, `get_field_evidence`,
  and owner-scoped `get_planner_result`. The selected region is fixed by the request;
  model tool arguments cannot substitute a different region or private owner.
- Exact water combinations only. Missing water stays missing. Analog episode tables and
  full-history paired counts are separate; water totals cover three campaigns.
- The planner card shows **optimum minus baseline**, its existing held-out intervals and
  conclusion. It does not label these as RL-minus-greedy intervals or food CVaR.
- No new runs, edits, external messages, web browsing or native-mobile assistant UI in this
  increment. Use the existing planner wizard to change weights and launch a run.

## Configuration and data sent to OpenAI

`OPENAI_MODEL` defaults to `gpt-6.1-sol` (verified available for the local key). The backend
reads `.env`, then `.env.local`, with process environment taking precedence. The production
Compose file passes the assistant settings to the backend only. Compose users can
load `.env.local` with an explicit additional `--env-file`; it is not copied into the image.

The provider receives the question, bounded recent history, source/method metadata,
selected public evidence and, only for authenticated planner chat, the caller's selected
simulation result. Credentials and authentication tokens are never included in those inputs.
Responses use `store=false`; this is not a claim of zero provider retention. Voice sends
the recording to OpenAI for transcription and a selected answer excerpt for speech.
Cropilot does not persist recordings or audio replies; they remain in request/browser
memory. Provider processing and retention are separate from this local behavior.

Public paid access defaults to disabled. Chat and transcription share 60 requests/hour
(`ASSISTANT_REQUESTS_PER_HOUR`) and two concurrent requests. Each message permits up to
four provider requests, three tool calls, 2,400 output tokens per request and a 35-second
SDK timeout per request, without automatic provider retries. Tool payloads are capped at
128 KiB. Limits are in-memory and reset on restart; deploy one backend process as already
required by the planner. Use an external persistent limiter before scaling publicly.

## Voice

The same backend `OPENAI_API_KEY` is used for chat, transcription and speech, provided its
project can access all configured models. `OPENAI_TRANSCRIPTION_MODEL` defaults to
`gpt-transcribe`; `OPENAI_SPEECH_MODEL` defaults to `gpt-realtime-2.1-mini`. No permanent
key, ephemeral token or direct provider connection is sent to the browser.

This is a recorded-turn voice agent, not a continuous call. The browser records at most
60 seconds and 4 MB, then calls `/api/assistant/transcriptions` (or the authenticated
`private-transcriptions` route). Cancel/close releases microphone tracks and aborts the
browser upload; a provider request already started can finish within its server timeout.
Before paid transcription, the server decodes with FFmpeg (15-second timeout, no external
media protocols), rejects audio longer than 60 seconds and normalizes it to mono 16-kHz WAV.
The user reviews the transcript before the usual evidence-backed assistant request.

With **Spoken reply** enabled, the backend reads the first cited claim and first limitation
over a server-side Realtime connection. Audio is labeled AI-generated and returned as WAV
alongside its transcript. Press Play to listen with native browser controls; reopening
history never autoplays previous answers. The speech transcript must match words, numbers and units
(punctuation/case may differ), otherwise only the full text is returned. This conservative
check can reject benign reformulations, including spelled-out numbers; it does not prove
the acoustic waveform is error-free. Speech never supplies new agronomic evidence.

Transcription has a 40-second SDK timeout, synthesis a 45-second overall timeout, no
automatic retries, and bounded output. A voice turn consumes a transcription request
plus an assistant request from the shared budget. Failed synthesis preserves the answer
and sources. Native Expo assistant/voice screens are not implemented by this change;
the responsive web panel is the demonstrated voice client.

Every answer paragraph requires at least one known source ID. Unknown sources fail closed;
unavailable provider errors expose no provider body. Schema/source checks do **not** prove
that every natural-language claim is supported: inspect the underlying table and evaluate
the answers. User history is untrusted, and numerical questions re-read tools each turn.

The prompt explicitly preserves spatial scale, provenance and time. JAS ONI is available
after a late-August decision, so these analog selections are retrospective. Water excess
is not a validated flood forecast. Soil carbon and food CVaR are not current planner goals.

## Verification

Voice increment, 2026-11-15: `pnpm test` returned **147 passed, 15 skipped**; the skips
are optional scientific environments/data. `pnpm lint` and `pnpm typecheck` passed.
Voice regressions cover auth/public opt-in, malformed/oversized audio, a valid 120-second
WAV under 4 MB rejected before transcription, numerical/sign/operator changes, WAV format,
text-only mode and preserving sources when speech fails. These tests make no paid calls.

The actual Chromium microphone-to-provider-to-player flow used a synthetic WAV input:
transcription HTTP 200, assistant HTTP 200 with speech in **21.8 seconds**, and a playable
21.8-second WAV excerpt. This is one observation, not a latency benchmark. An earlier
speech request timed out; its cited text remained available. A separate direct synthesis
of that excerpt succeeded in 6.5 seconds. Lifecycle checks replayed the saved successful
response without paid calls: pause/play, microphone release on close, denied permission,
no historical autoplay, no page exceptions and no overflow at 390×844. Physical microphone,
Safari and native Expo voice have not been tested. Artifacts remain outside Git.

`uv run pytest tests/test_assistant.py -q` covers exact water values, invalid combinations,
missing regional water, invented/missing citations, owner checks, rejected private IDs on
the public endpoint, concurrency/budget release, real SDK tool round trips with a mocked
HTTP transport, bounded tool loops and sanitized provider errors. No live calls in tests.

Initial live check with `gpt-5.4-mini` on 2026-11-15: the browser comparison returned HTTP 200 in 5.8 seconds
(one observation, not a latency benchmark; a later check took 13.3 seconds),
called `compare_rotations` and supplied ten
source records. Checked desktop 1440×1000 and mobile 390×844, evidence expansion and
conversation reset. No page exceptions or horizontal mobile overflow. The one observed
console error was the optional auth request's 502 with auth not running.

Private ownership is tested offline. A real Google-login-to-planner conversation has not
been exercised in this local environment. Existing optional model tests skip when their
separate datasets/environments are absent; no scientific validation is inferred from UI tests.

One live answer incorrectly described the reference's zero **difference** as zero absolute
deficit and called lower unmet demand water savings. Added explicit metric definitions to
both tool evidence and the instruction, plus a regression on their presence. This observed
failure illustrates why citations alone cannot guarantee scientific correctness; numerical
tables remain the reference and agronomic review is still needed.

The default was then changed to `gpt-6.1-sol`: a same-question API check completed in
10.7 seconds and retained the unmet-demand terminology. This is a small manual comparison,
not an accuracy benchmark; users can configure a different accessible model explicitly.
